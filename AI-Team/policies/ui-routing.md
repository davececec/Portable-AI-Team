# 按需 UI/UX 路由

| 情形 | AgentC |
| --- | --- |
| 新建主要界面、整体改版、用户明确要求美化 | 调用：设计及实现后实际截图/交互检查 |
| 纯后台、脚本、接口、数据库任务 | 默认跳过 |
| 局部文字/颜色小改、简单任务 | 默认跳过，不额外增加调用 |

流程：AgentA 整理需求 -> 按需 AgentC 设计 -> AgentB 实现 -> 按需 AgentC 实际截图/交互检查 -> AgentA 独立验收。跳过 C 时直接 A -> B -> A。C 的检查不能替代 A 最终验收；用户仅与 A 沟通。

默认 C 设计、B 实现。C 不修改业务逻辑、数据库或接口；只有 A 明确授权时可改指定纯视觉文件。禁止 C/B 并发编辑同一文件；业务开发仅在接口清楚且文件不冲突时并行。

C 每次使用干净最小上下文，禁止继承完整会话：只给工单、项目、允许范围、相关页面文件、已有设计规范与完成条件；检查时仅增量给规范和运行入口。优先复用现有设计规范。反馈合并后由 A 派单，同一任务最多自动返工 2 轮，超限由 A 汇总阻塞，不得重启 C 规避上限。

没有子智能体能力时明确报告“顺序降级：角色顺序模拟”，按 A -> 按需 C -> B -> 按需 C -> A 执行；不能声称独立 C 或干净上下文隔离。A 阶段仍需重新运行验收，不把 B 自测当独立验证。

没有浏览器/截图能力时报告“未验证”，不得伪造视觉通过。规范、截图、视觉报告留在业务项目；胶囊只携带稳定可复用偏好摘要。
