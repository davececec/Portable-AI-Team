# Low-Token V2 工作流

需求 -> 紧凑工单 -> 按需 AgentC 设计 -> AgentB 直接修改共享文件 -> 按需 AgentC 实际截图/交互检查 -> 紧凑交付 -> AgentA 独立验收 -> 必要时返工 -> 交付。新建主要界面、整体改版、明确美化时调用 C；纯后台和文字/颜色小改默认跳过，详细边界见 `../policies/ui-routing.md`。

1. 默认 `balanced`；用户入口仍是“ZH，给我做一个……”。
2. AgentA 先读 `memory/index.md`，只选 1-3 个相关分类；恢复旧项目时只读当前工单、相关报告和必要源码。
3. 微型任务用 `task-micro.md`，标准任务用 `task-standard.md`。工单不得重复完整聊天历史。
4. AgentB/C 派单仅包含工单路径、项目路径、允许修改范围、必要文件列表、完成条件与相关既有设计规范，禁止继承完整会话。默认 C 设计、B 实现，禁止并发编辑同一文件。
5. AgentB 在共享文件系统修改，交付仅列修改文件、测试结果和风险。
6. AgentA 独立运行测试。确定性检查直接按结果判定；UI、语义和主观标准才由 AgentA 分析。
7. 返工内容限制为失败用例、期望/实际、相关文件和最多 30 行日志。最多自动返工 2 轮，此后交由用户选择方案。
8. 完成时顺手记录新且稳定的经验，不为记忆单独调用模型。每次工单验收后，AgentA 检查偏好/缺陷/方案/决策/里程碑五类，有新经验写对应记忆文件并在工单尾部标注；无则跳过不虚增。

无子智能体能力时明确报告角色顺序模拟，不声称独立 C 或干净上下文隔离。没有浏览器/截图能力时 C 必须报告未验证。合并反馈，同一任务最多自动返工 2 轮；规范和截图留在业务项目，胶囊仅保存稳定可复用偏好摘要。
