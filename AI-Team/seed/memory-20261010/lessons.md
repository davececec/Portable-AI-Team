# 经验

- 2026-09-24 交接旧项目时，必须同时检查 Git HEAD、近期提交、未提交工作区、实际启动配置和运行探活。README、部署包和汇报文档可能不同步；交接中应标注事实来源优先级、过期结论和未验收功能，不能把“源码存在”写成“发布完成”。
- 2026-09-24 多服务项目的“端口监听”和 HTTP 200 不能代表数据库可用。健康检查必须分别报告进程、HTTP、数据库及关键依赖状态；数据库权限应使用独立测试对象完成 CRUD，并通过事务回滚或显式清理验证无残留。
- 2026-09-24 Windows SQL Server 排障先发现实例名、服务状态和实际监听端口，再测试凭据；命名实例不一定监听 1433。涉及凭据时只记录成功/失败和错误码，不把密码写入文档、记忆或代码。
- 2026-09-27 pyodbc 两个坑：`executemany` 第二参数不能为空列表（否则报 ProgrammingError），空数据前要先判断；`datetime.day`（int）和 `date` 比较永远为 True，跨天判断要用 `datetime.date()`。
- 2026-09-27 PowerShell 里 `Invoke-RestMethod` 输出中文乱码是控制台编码问题，接口本身返回 UTF-8 正常；验证时先设 `[Console]::OutputEncoding = [Text.Encoding]::UTF8` 再打印。
- 2026-09-27 厂区内网/无外网环境下交付前端，任何 CDN 引用（图表库、在线字体、图标）都会直接加载失败导致页面空白或图表缺失。前端依赖必须下载到本地 static 目录再引用，交付前专门排查残留外链。
- 2026-09-27 SQLite 开启 WAL 后，直接复制运行中的 .db 文件会得到损坏或不完整副本。正确做法：先停止写入进程，或同时复制 .db / .db-wal / .db-shm 三个文件。
- 2026-09-27 工业设备参数在空闲/非生产时段常自然归零（流量、电流、转速都可能为 0，甚至出现小幅负值）。给这类参数设下限报警，会在非生产时段持续误报；应先只设上限，下限待工艺确认后再开。
- 2026-09-27 高频采集下（如 5 秒一次）逐条写报警记录会产生报警风暴，单参数每天可积累上万条。应改为事件式去重：只在“开始越限”和“恢复正常”各写一条，持续越限只更新内存。
- 2026-09-27 Flask debug 模式模板会自动热重载，但新增路由不会生效：页面看着是新版，接口却 404，容易被误判成代码写错。改完必须重启进程再验证。
- 2026-10-08 工业同步脚本 time.sleep 值与注释不一致是常见事故源：PBS 同步代码写 sleep(36000)（10 小时）注释写"休眠 5 分钟(300秒)"，导致新车 10 小时内不可见。审计时必须搜索所有 sleep 调用逐一核对实际秒数与业务期望周期，不能信任注释。
- 2026-10-08 现场用户说"数据不准"时优先排查同步间隔而非计算逻辑：增量同步延迟 + 计划同步延迟叠加，会让参考车定位错、新排产车缺失、A11 消车慢，表象全是"不准"。先缩短同步周期再看残留问题，不要直接改展示算法。
- 2026-10-10 Windows 管道会放大启动器挂起风险：子进程继承 stdout/stderr/stdin 后，带 `| Out-Null` 的命令可能长时间不返回；直接退出测试也可能被误判。验收启动器时要无管道直跑、记录 exit code，并单独验证 -Stop 后无项目残留进程。
